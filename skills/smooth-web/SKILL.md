# Smooth Web: Interface & Product Copywriting

Smooth Web bridges visual design and linguistic precision. It eliminates generic SaaS fluff (*"Empower your workflow"*, *"Unleash the power of AI"*) and replaces it with clear, actionable, and human microcopy designed for modern web applications and landing pages.

---

## 1. Domain Principles for Web & UI

### 1.1. The Hero Section Standard
* **Rule:** Never use vacuous superlatives (*"The definitive platform"*, *"The future of X is here"*).
* **Formula:** `[Concrete mechanism or direct action] + [Tangible unadorned outcome]`.
  * ❌ *"Take your development workflow to the next level with cutting-edge AI."*
  * ✅ *"Audit dependencies and catch vulnerabilities in your terminal before each deployment."*
  * ❌ *«Eleva tu experiencia de desarrollo al siguiente nivel con IA de vanguardia.»*
  * ✅ *«Audita dependencias y detecta vulnerabilidades en tu terminal antes de cada despliegue.»*

### 1.2. Microcopy & Button Labels (CTAs)
* **Rule:** The button text must describe the exact event that occurs when clicked, not an emotional aspiration.
  * ❌ *"Start your journey"*, *"Discover the magic"*, *"Unlock possibilities"*.
  * ✅ *"Create free account"*, *"Download for macOS"*, *"View live demo"*.
  * ❌ *«Comienza tu viaje»*, *«Descubre la magia»*, *«Empieza a transformar»*.
  * ✅ *«Crear cuenta gratuita»*, *«Descargar para macOS»*, *«Ver demo en vivo»*.

### 1.3. Error Messages & Form Validations
* Never blame the user (*"You entered an invalid input"*).
* Never leave the user stranded with a generic code (*"Error 500: Something went wrong"*).
* State: 1) What occurred in plain language, and 2) The exact corrective action.
  * ❌ *"Validation error: Password field does not meet system security criteria."*
  * ✅ *"Password requires at least 8 characters and one number."*
  * ❌ *«Error de validación: El campo contraseña no cumple con los requerimientos exigidos por el sistema.»*
  * ✅ *«La contraseña requiere al menos 8 caracteres y un número.»*

### 1.4. Empty States & Onboarding
* Avoid patronizing or falsely enthusiastic cheerleading (*"Wow, look how empty it is here!"*, *"Time to make great things happen!"*).
* Provide immediate spatial orientation and one primary action.
  * ❌ *"Your inbox is waiting for adventures. Create your first project today!"*
  * ✅ *"No saved projects yet. Create a new project or import an existing file."*

### 1.5. Feature Grids & Value Propositions
* Every feature card must pass the **Portability Test**: describe the exact feature mechanism and what user problem it solves.
* Avoid: *"Intuitive design"*, *"Blazing fast performance"*, *"Bank-grade security"* unless backed by specific verifiable metrics (e.g., *"AES-256 encryption at rest"*, *"Sub-50ms query response time"*).

## 2. Quick Reference Checklist for UI Copy

- [ ] Do button CTAs begin with specific action verbs?
- [ ] Does the Hero copy communicate what the product does within 3 seconds?
- [ ] Were generic buzzwords purged (*intuitive, disruptive, empower, ecosystem, seamless*)?
- [ ] Do error messages provide an immediate resolution path without blaming the user?
- [ ] Is microcopy tested for mobile viewports and accessible screen readers (a11y)?
